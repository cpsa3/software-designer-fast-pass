# 01-系统架构下午案例分析通用破局三段论

> **战略权重**：★★★★★（**下午案例分析 75 分及格生命线** ｜ 90 分钟 3 道大题答题规范）  
> **试卷结构**：**试题一为必做题（25分，100%考架构评估与质量属性）** ＋ **试题二至试题五选做 2 题（各25分，覆盖微服务、分布式存储、云原生、嵌入式/大数据）**。

---

## 一、 考场答题“三段论”标准化得分范式

案例分析是阅卷老师在电脑屏幕上手动打分。阅卷老师平均每道题阅卷时间仅有 **30~45 秒**，因此**严禁写成不分段、无要点的“小作文”**！必须执行**“结论先行 + 标号分点 + 踩分关键词加粗 + 扣题回溯”**的答题范式：

```
【标准得分三段式模板】
1. 【定性定论】一句话直接给出最终技术选型或判据结论（如：该设计属于敏感点 / 建议选择方案 B）。
2. 【核心原理与采分点】用 1~2 句话阐明所依据的架构原理（如：根据 CAP 定理 / 因为支持增量数据流并行推进）。
3. 【结合题干业务反推】用半句话将原理与题干中的具体系统特征强绑定（如：从而满足题干中 10 万并发下 500ms 响应的性能指标）。
```

## 二、 试题一（必选题 25分）三大标准设问破局法

### 设问 1：质量属性分类与场景识别（8~10分）
* **题型模式**：题干给出一段系统描述（包含 4~5 个具体业务场景需求），要求考生指出每个场景分别属于哪种质量属性，或者完成表格匹配。
* **破局要点**：
  1. 找数字与指标：
     - 带“响应时间”、“吞吐量”、“并发量” $\implies$ **性能 (Performance)**
     - 带“宕机”、“故障自动转移”、“双机热备”、“99.99%可用” $\implies$ **可用性 (Availability)**
     - 带“加解密”、“防篡改”、“身份鉴权”、“数字签名”、“防攻击” $\implies$ **安全性 (Security)**
     - 带“未来增加新渠道/新业务”、“低耦合”、“不修改已有代码” $\implies$ **可修改性 (Modifiability)**
  2. 规范书写：必须使用官方标准名词，严禁自创词汇（如不能写“易扩展性”，只能写“可修改性”）。

### 设问 2：敏感点、权衡点、风险点分析（8~10分）
* **题型模式**：要求从架构师的几个设计方案中，指出哪个是敏感点，哪个是权衡点，并说明理由。
* **破局套路**：
  - **敏感点格式**：*“设计 X 是针对【属性 Y】的敏感点。理由：修改设计 X 直接影响系统的【属性 Y】（解释该属性变好或变坏）。”*
  - **权衡点格式**：*“设计 X 是【属性 A】与【属性 B】之间的权衡点。理由：设计 X 提升了系统的【属性 A】，但带来了开销，降低了系统的【属性 B】。”*（**必须写出一升一降两个属性！**）

### 设问 3：架构风格对比与选型决策（5~7分）
* **题型模式**：对比方案 A（如管道-过滤器）与方案 B（如面向对象/批处理），问你支持哪种方案并说明优缺点。
* **答题万能模板**：
  - *“我赞同方案 A。理由如下：”*
  - *“① 优点（支持采分点）：方案 A 具备高吞吐率、构件解耦独立演进、支持增量并行处理的优势，高度匹配题干中实时流式处理的需求；”*
  - *“② 缺陷克服：方案 B 存在全局数据共享耦合度高、必须整体批处理等待导致延迟过大等缺陷，无法满足系统的响应指标要求。”*

## 三、 选做大题（微服务 / 缓存一致性 / 分布式系统）通用采分模板

### 场景：为什么不能用传统单体数据库？为什么要引入微服务与分库分表？
> **采分要点**：
> 1. **单点瓶颈与高可用**：单机数据库存在连接数与磁盘 I/O 物理上限，无法承载峰值流量，且存在单点故障风险（SPOF）；
> 2. **业务边界解耦与团队自治**：微服务基于 DDD 限界上下文拆分，使得核心业务（订单/支付）与外围业务独立部署、独立扩缩容，故障相互隔离；
> 3. **读写分离与分库分表**：通过 Sharding 水平切分分散磁盘读写压力，利用读写分离分流大量只读请求。

### 场景：如何保证 Redis 缓存与 MySQL 数据库的数据一致性？
> **采分要点**：
> 1. **更新策略**：采用先更新数据库，再删除缓存（Cache-Aside）的基础策略；
> 2. **异步补偿兜底**：为了防止高并发下删除缓存失败导致脏读，引入阿里 Canal 监听 MySQL Binlog 变更日志，将数据变更消息异步发送至 Kafka/RocketMQ；
> 3. **幂等重试消费**：由专属消费者拉取消息执行缓存删除，并配置指数退避重试机制，实现业务解耦与毫秒级最终一致性。

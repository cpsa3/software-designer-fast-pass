### 试题一：数据流图 DFD（农事管理服务平台）—— 实得 12.5 / 15 分

  * `E1: 平台管理员`
  * `E2: 农户`
  * `E3: 租户`
  * `E4: 第三方软件`
* **标准采分**：`E1: 平台管理员`、`E2: 农户`、`E3: 租户`、`E4: 第三方软件`（或第三方系统/APP）。
* **复盘亮点**：

  * E2 接收“农事提醒”并上报“农事活动”，直连说明(3)“农户进行农事活动并记录”；

#### 2. 【问题2】数据存储 D1~D4 识别（4分）—— 实得 4.0 / 4.0 分（满分拿下！）

  * `D3: 农事过程`
  * `D4: 农事活动`
* **标准采分**：
  * `D1: 人员表（或人员）`
  * `D2: 基地及地块数据表（或地块信息 / 基地及地块数据）`

#### 3. 【问题3】补全 4 条缺失数据流及起止（4分）—— 实得 1.2 / 4.0 分（核心失分靶区）
* **考生现场作答与逐条诊断**：
  1. `起点: D4 终点: P4 数据流: 投入品实际消耗` $\implies$ ✔ **命中！得分 1.0 分**。
     - 题眼依据：说明(4)“农户在农事活动中设定投入品的实际消耗”，P4 要统计投入品使用情况输出给 E3，必须从 D4（农事活动）读取投入品实际消耗。
  2. `起点: D4 终点: P4 数据流: 农事活动` $\implies$ ❌ **失分 1.0 分（手滑与终点漂移）**。
     - 诊断：考生与第 1 条写了完全相同的起点和终点（两个 `D4 -> P4`）！考生本意想写把农事活动送去信息服务比对，但手滑将终点错写为了 P4（应为 P5）。
  3. `起点: D1 终点: P5 数据流: 人员` $\implies$ ❌ **失分 1.0 分（伪造非必要读流）**。
     - 诊断：说明(5)明确指出信息服务 P5 针对的是“相关地块农事活动实施情况（如与农事过程比对）”，P5 的查询由各涉众发起，并不需要从 D1 人员库拉取全员清单。
  4. `起点: D4 终点: P5 数据流: 农事过程` $\implies$ ❌ **失分 1.0 分（源头张冠李戴）**。
     - 诊断：致命混淆！“农事过程”保存在 **D3** 里面，D4 保存的是“农事活动”！考生把两者的物理库搞反了。
* **标准缺失流清单（完整采分点）**：
  * ① **`起点: D4, 终点: P4, 数据流: 投入品实际消耗`**（或 投入品消耗 / 投入品使用）
  * ② **`起点: D4, 终点: P5, 数据流: 农事活动`**（或 农事活动实施情况 / 农事活动信息）
  * ③ **`起点: D3, 终点: P5, 数据流: 农事过程`**（或 农事过程信息）
  * ④ **`起点: D3, 终点: P3, 数据流: 实施计划`**（或 农事过程 / 农事过程及实施计划）

#### 4. 【问题4】“农事信息请求”数据流组成（3分）—— 实得 3.0 / 3.0 分（满分拿下！）

### 试题二：数据库设计 (E-R)（汽车零件采购系统）—— 实得 12.0 / 15 分

## 🎯 三、命题陷阱透视与考场自愈锦囊

### 1. 【试题一 DFD】“存储双黑洞”机械化排查（破局必杀技）
在 0 层图中，审视 D3 与 D4：
* **D3（农事过程）**：P3 写入农事过程后，D3 没有任何读出线，是一个**纯黑洞**！
  - 问两句：① 谁要拿它比对？$\implies$ P5 信息服务（补 `D3 -> P5`）；② 谁要拿它定时提醒？$\implies$ P3 种植管理需要实施计划（补 `D3 -> P3`）。
* **D4（农事活动）**：P3 记录农事活动后，D4 没有任何读出线，也是一个**纯黑洞**！
  - 问两句：① 谁要拿它算投入品？$\implies$ P4 投入品管理需要实际消耗（补 `D4 -> P4`）；② 谁要拿它看完成进度？$\implies$ P5 信息服务需要对比农事活动（补 `D4 -> P5`）。
* **成双成对闭环**：D3 贡献两条出流（给 P3、P5），D4 贡献两条出流（给 P4、P5），4 条缺失流直接秒杀！

### 2. 【试题一 DFD】区分“静态计划”与“动态流水”
* **D3 是计划（标准）**：由租户预先设定，不可轻易变动，是衡量进度的尺度。
* **D4 是打卡（现实）**：由农户日常打卡产生，包含投入品消耗与活动记录。
* **绝对严禁将 D3 的数据归于 D4！**

### 3. 【试题二 数据库】三元联系判定与属性命名“照妖镜”
* **三元联系判定法则**：固定任意两个实体看第三个实体的基数，三端均可取多个，判定为 $m:n:p$；
* **属性命名绝对一致性**：写任何属性名前，必须回看上下文（是“编码”还是“编号”，是“工号”还是“员工号”），严禁凭生活经验自由发挥；
* **多对多扩展独立建表**：实体独立建表；多对多联系独立建表，引入两端主键并挂接联系属性，联合主键即双外键。
